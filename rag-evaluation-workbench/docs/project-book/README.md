# The Project Book

| Edition | File |
|---|---|
| PDF (A4, bookmarks, clickable contents) | [`RAG_Evaluation_Workbench_Project_Book.pdf`](RAG_Evaluation_Workbench_Project_Book.pdf) |
| Single-file Markdown | [`PROJECT_BOOK.md`](PROJECT_BOOK.md) |
| Chapter sources | [`chapters/`](chapters/) — edit these, then rebuild |

Supporting assets: `figures/` (SVG diagrams, generated by `tools/diagrams.py`), `screenshots/` (captured from the
running app by `tools/capture_screenshots.py`), `generated/` (appendices produced from the code by
`tools/generate_reference.py`).

## Rebuild

```bash
uv sync --group docs
uv run python docs/project-book/tools/diagrams.py
uv run python docs/project-book/tools/generate_reference.py
uv run python docs/project-book/tools/build_book.py
```

`build_book.py` needs Chrome or Edge for the PDF (`--no-pdf` skips it). After printing, it checks that every Part
heading exists and starts a page, and renders sample pages to `build/pages/` for inspection (`build/` is not kept).

Screenshots need the app running on port 8501 and the demo runs:

```bash
uv run python scripts/seed_demo_runs.py --pages docs/project-book/tools/screenshot_pages.json
uv run python docs/project-book/tools/capture_screenshots.py --pages docs/project-book/tools/screenshot_pages.json --out docs/project-book/screenshots
```

## How it was written

Parts I, II, X and XII were written by the lead engineer; Parts III–IX and XI were drafted by writer agents
working from the code under an evidence rule (every claim checked against the source or a command's output, line
references verified), then revised after the code fixes their review prompted. Line references were re-checked
mechanically after the final code change (no reference falls outside its file or has a reversed range). Where the
book and the code disagree, the code is right.
